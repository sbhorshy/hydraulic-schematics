# 上篇 · 规格（spec）

## 1. 概述

### 1.1 目的与范围

本文记录 `sbhorshy/hydraulic-schematics` 仓库的现状与契约。仓库核心是一套 **agent 技能** `.agents/skills/hydraulic-schematic/`：从**唯一输入定义**（SysML v2 模型，或 L0 `intent.yaml` + `layout.json`）出发，复用已标注描边符号库绘制液压系统原理图 SVG，生成行号级追溯清单，并以「几何校核 → 感知回读」闭环验证后交付。覆盖范围：技能本体、符号库与组件 catalog、闸门工具链、双链路（SysML / L0）、以及 `1#系统原理图/` 端到端实证工作区。

### 1.2 术语与约定

| 术语 | 含义 |
|---|---|
| 链路 | 出图路径。**SysML 链路**（整机，`*.sysml` 输入）；**L0 链路**（分系统，`intent.yaml`+`layout.json` 输入）。两链路共享符号库、视觉常量与校验理念，不混用 |
| 母线 | 竖直汇流线（绘图抽象），如 `@PRESS/@MANIFOLD/@USR/@USERR/@RET/@CASE`；拓扑上以枢纽端口星形编码，不建 n 元 connection |
| taps | 传感支路（如感温/感压），不入 `paths`，以 `{sensor, at}` 挂接，dangling 豁免 |
| intent | L0 输入意图文件（章节：`l0_version/system/catalog/maturity/extern/parts/paths/groups/taps/unknown`） |
| 受控清单模板 / 拓扑确认单 | 转写对账机制的前后两件：模板约束清单书写，确认单供工程师逐行签认 |
| 成熟度（符号） | `annotated`（可直接绘图）／`provisional`／`draft`——后两档按 CONCEPT 档降级使用并在图签披露 |
| 成熟度（图面） | intent/layout 的 `maturity` 字段；现状承诺档位为 **concept 概念图，非工程放行图** |
| 闸门 | 校验闭环中的强制检查点，共 7 道（§6） |
| 构图预算 | 数值化构图契约 B1–B7（线交叉、折返、绕行比、最短段、净距、走廊、标签净空） |
| V 系列 | `validate_sheet.py` 几何校核检查项编号（V1–V19） |

### 2.5 双链路总览与 1# 端到端实证

- **SysML 链路**：`.sysml` v2 → `render_aircraft_schematic.py` → SVG + 追溯清单；金样回归走 selftest A。
- **L0 链路**：`intent.yaml + layout.json` → preflight（强制）→ `render_l0_sheet.py <workdir>` → `validate_sheet.py <workdir>` → PNG 感知回读。

**1# 系统实证**（`1#系统原理图/`，到站判定三把尺全过）：工程师清单 18 项 → 22 个受控实例（含 8 只 hydraulic_user 名框）+ 2 条气侧 taps；33 条二元 connect = 37 条液压边 + 2 taps（nets=37 / segments=48 / junctions=20）；`validation-report.json` **fail 0 / warn 6**（与现状基线同口径）；技能链端到端全自动出图 **77.7 秒、零手工坐标、零返工轮、零人工介入**（证据 `skill-chain-e2e/` 与 `proto/frozen/driver-runs/arrival/`）。效率对照：手工基线约 2 小时 / 4 轮返工 / 3 类介入点；校核驱动器演练 91.6s（原 940.9s，10.3×）。

## 3. 不变式与规则优先级

**四条不变式（任何阶段不得违反）**：

1. **可追溯**：图中任一组件/端口/连接/图元追溯到唯一输入定义——SVG 带 `data-node`/`data-port`/`data-edge`/`data-sysml-line`（L0 为 intent 锚点）/`data-zone` + 追溯清单 markdown。
2. **不编造拓扑**：类型不在目录内则其端口不存在，不得出现在 paths/连线；数量未声明按 1 实例；不知道怎么连写 intent `unknown:` 段，不画。
3. **确定性优先**：布局坐标显式给定（layout 显式坐标或引擎规则式解），端口坐标从符号 `connection-points` 实读，不硬编码。
4. **校验不过即是失败**：结构自检失败退出码 1 终止；无回读图的校核项记"未校核"，不静默放过。

**规则优先级**（冲突裁决，高→低）：用户显式要求 > 符号/风格约定 > 图类布局规则 > 通用默认。唯一不可豁免下限是 Phase 4 校验闭环：任何上层要求（包括用户显式要求）不得跳过或弱化三层闸门；冲突时要么修图重跑直至全绿，要么逐条披露后按概念图降级交付——不带病通过，不静默截断。

## 4. 输入契约

### 4.1 SysML 链路

`part`（实例化层次）/ `port`（不标方向）/ `connect a.b to c.d`（二元，逐语句记行号供追溯）。母线为绘图抽象，以枢纽端口星形编码；平台/概念级简化允许但必须在追溯清单"简化说明"披露。渲染器内置结构自检：每条 connect 有对应画出边、每个实例 part 有对应节点，缺失即退出码 1 不出成品。

### 4.2 L0 链路（intent.yaml）

- `parts` 只收目录内类型（`id: component_type`）；`paths` 端点用 `实例.端口` 或 `@母线名`，目录外类型不得出现；传感链不入 paths 走 `taps`；存疑数量/接法显式写 `unknown:` 不代为编造；`catalog:` 引用已冻结修订号否则注明。
- **preflight 强制预检**（渲染器 parse 后、布局前）：形状层（JSON Schema，违规报 JSON 路径）+ 语义层（目录一致性/端口存在性/main_path 裸实例/role 兼容/medium 兼容/引用一致性/terminal 端点合法性）+ 模板门禁（同目录存在受控清单模板即三向对账，差异=ERROR；签认按 maturity 分级：concept 未签认=WARN 披露放行，其余=ERROR 扣产物）。任何 ERROR 扣留 layout/svg/topology，退出码 1。
- 用户（用油设备）不需新符号：`parts` 写 `<inst>: hydraulic_user`，名框由渲染器写框内名并省略框外标签。

### 4.3 布局契约（layout.json）

显式坐标契约：`canvas / canvas_shift_x / style / externs / nodes / buses / labels / label_pos / lanes / vlanes / group_padding / legend / title_block / revision_log`——**不做自动布局**（引擎规则式解见 §13 R1）。在途变更（[#23 坐标契约显式化](https://github.com/sbhorshy/hydraulic-schematics/issues/23)）：`canvas_shift_x` 双坐标系将废除，改为自声明 drawable 矩形 + 显式 `EDGE_MARGIN`；spec 现行口径仍含 `canvas_shift_x`，升版时随 #23 落码改写本节。

### 4.4 组件类型与端口契约

catalog 各字段语义、`enums`（medium/port_role/flow_capability/anchor_direction/connection_role/symbol_status）、成熟度降级与 `drawing_blockers` 披露口径见 references/symbol-library.md。端口契约变化属目录修订：递增 `catalog_revision` 并记录冻结状态；`draft_not_frozen` 期钉号不可复现，intent 引用须注明。

## 5. 符号与渲染规范

- **标注**：复制 `_template.svg` 起稿（描边几何、width/height 与 viewBox 一致无单位、端口落边界、status/source-ref 根属性、"依据/未确认项"注释）；按 API 加 `connection-points`；更新 catalog 并递增 revision；过入库门禁后入规范源库。渲染端读端口必须处理 viewBox 原点偏移与缩放，不硬编码任何端口坐标。
- **视觉**：线型由端口 role+medium 推导（class：hi/med/lo/mech/sig）；流体边带箭头，机械边不带；吸油语义从油箱口到泵 suction 口跨串联组件传播。线宽/镜像/分区框/标签（中英双行，中文主名）/图签图例完整约定见 references/rendering-rules.md。
- **数值构图预算（concept 档 v1）**：B1 线线交叉恒为 0（无桥接豁免）；B2 折返单线 ≤3 且全图 ≤40；B3 绕行比 ≤1.5（边界走廊 ≤4 须披露）；B4 最短走线段 ≥8px；B5 节点盒净距 ≥40px；B6 容器走廊 group_padding ≥14、避让走廊 ≥12；B7 标签净空 ≥6px。B1 硬 fail，其余超限走 V19 WARN。
- **符号引用**：`<image>` href 相对活动库根——解析顺序：工作目录相对（本地覆盖）优先，否则锚定 catalog 同目录（即 skill 规范源库，工作目录无需库拷贝）；目录外或未标注符号画干净描边框图并在图签栏披露。
- **追溯清单**：`<name>_topology.md` 两张表（连接边映射、节点 part 映射），每行注明输入定义行号/锚点与实例数；概念级简化在文末逐条披露。

## 6. 校验闭环（7 道闸门）

| # | 闸门 | 把什么门 | 失败行为 |
|---|---|---|---|
| 1 | 渲染器结构自检（两链路内置） | 拓扑完整性：connect↔边、part↔节点 | 退出码 1，不产出成品 |
| 2 | `preflight.py`（L0 强制） | 输入合法性：形状+语义七类+模板对账/签认分级 | ERROR 扣留产物，退出码 1 |
| 3 | `check_library.py`（pre-push 接入） | 库结构 L1/L2/L3 + WHITELIST 挂账 | 退出码 1；越闸须 `--no-verify` 并披露 |
| 4 | `selftest.py` | 出图能力回归（金样/闸门沙箱/负正例） | 退出码 1；改符号/catalog/模板后必跑 |
| 5 | `validate_sheet.py` | 几何 V1–V19 + 预算 B 面板 + 三件套互核 | `validation-report.json`；退出码 1=failed |
| 6 | 感知回读（PNG） | 符号变形/镜像/穿越/标签对位/图签图例；每轮回读前强制重出 `-w 1680` 1:1 PNG | 疑点修正后重光栅化再回读，不得跳过 |
| 7 | 有界收敛（流程闸门） | 修正最多两轮，每轮只修上一轮列出的缺陷 | 两轮不绿即停手，交"未收敛项清单"给工程师决策 |

**交付判据（三者齐备）**：渲染脚本退出码 0 + `validation-report.json` 全绿 + 最新 PNG 已回读并记录校了什么。

## 7. 运行纪律与单源纪律

- 渲染/校验模板脚本先复制到工作目录再修改运行（历史复制纪律）；#21 起技能链脚本接受可选**工作目录参数**，就地运行、无需复制、工作目录不再需要 `symbols/` 拷贝——为首选口径。
- 守门工具 `check_library.py` / `selftest.py` 是 skill 基础设施：不复制，按 SKILL.md「随附资产与单源纪律」原位命令从仓库根运行。
- 库演进流程：改符号/catalog → `check_library.py` → `selftest.py` → 提交（pre-push 钩子兜底）。

# 下篇 · 产品需求（PRD）

## 9. 产品定位与承诺边界

**一句话定位：agent 可靠驱动的液压原理图生成链路——唯一输入定义 → 闸门全绿出图，新系统零改接入。**

**成熟度承诺上限：concept 概念档**（图签口径「成熟度： concept 概念图，非工程放行图」）。产品交付的是设计支持与评审辅助用的概念图；**工程放行永远须经人工原图级签认**，不在本产品承诺范围内。此上限与不变式「概念图降级交付」自洽。

## 10. 目标用户与人机分工

**agent 会话为主、工程师复核为辅。** 主要消费者是 AI 会话（工程师下指令，agent 跑 skill 出图）；工程师负责给意图（intent/layout）、审签认（拓扑确认单逐行签认）、收未收敛项决策。由此推出的需求侧重：**agent 可用性**（契约刚性、退出码语义、失败即停）、**闸门不可绕过**（任何指令不得弱化 Phase 4）、**文档自助可读**（SKILL.md/references 即 agent 的操作手册）。

## 11. 核心使用场景

基于现有 skill 的**全部场景**均为产品范围：

| 场景 | 输入 → 交付 | 现状 |
|---|---|---|
| S1 L0 清单一键出图 | intent+layout → 原理图+追溯清单+校验报告 | 1# 端到端实证（77.7s 零介入） |
| S2 SysML 整机链路 | `*.sysml` → 整机原理图+追溯清单 | 可用，金样回归覆盖 |
| S3 既有图纸更新 / 新系统接入 | 增删组件改 intent/layout 重跑；新系统只写 intent+layout | 可用；零改接入是 §12 验收口径 |
| S4 符号库/catalog 扩充 | `_template` 起稿 → 入库门禁 → catalog 登记 | 可用；门禁归位见 R3 |
| S5 布局寻优（增强方向） | 引擎规则+守门+寻优三阶段 | 1# 内已证（B3 1.447）；通用化见 R5 |

## 12. 成功标准与验收口径

1. **一次通过率：闸门全绿、人工介入趋零。** 口径：交付判据三件齐备（§6）；人工介入点（手工坐标、手工修图轮、人工裁决）逐单计数趋零。参照实测：全自动 77.7s 零返工零介入 vs 手工 ~2h 四轮返工。
2. **可复用性：新系统零改 skill 接入。** 口径：接入第二套系统时 `assets/`、`scripts/`、闸门与规范零改动，只新增该系统的 intent/layout（必要时扩符号/catalog，走 S4 流程）。

## 14. 非目标

- **工程放行档**：承诺上限为 concept 档（§9）；放行级签认体系、工艺级符号语义不在本产品范围。
- **对外产品化/多租户交付**：目标用户为内部 agent 会话与工程师（§10）；版本化对外承诺、脱敏与支持口径不做。
- **黑盒自动布局**：布局走「规则式分层 + 约束守门 + 预算寻优」三阶段（方案乙），不做无人审查的元启发黑盒。
- **演示图谱域外能力**：GIF 动效、interactive HTML 导出、12 风格体系（沿[能力抬升地图](https://github.com/sbhorshy/hydraulic-schematics/issues/1)裁决）。

## 15. 文档维护机制

- **单一来源分工**：规范性来源 = skill `SKILL.md` + `references/`；本文档 = 现状快照（spec 上篇）与需求登记（PRD 下篇）。冲突时以 skill 为准，并视为本文档的过期。
- **更新时机**：随沉淀批工单（R1–R3）落码各更新一版（§4.3 的 canvas_shift_x 注记随 R2 改写）；需求状态变化随票更新 §13；版本号递增并保留评审 issue 链接。
- **评审**：本 v0.1 的评审入口见仓库 Issues 评审帖；评审意见落票，修订随版。
