# Domain docs

采用 **single-context**：根目录一份领域术语表，架构决策放 `docs/adr/`。

## 探索前读取

- 当前已有术语表是根目录 `CONTEXT.md`，先读取它，并沿用装配、围框、成员、越框端口、分组框、枢纽和星形编码等已有定义。
- 目标标准位置为根目录 `GLOSSARY.md`。今后迁移时保持一份术语规范源：迁移已有定义，并将 `CONTEXT.md` 更新为指针，避免维护两份内容。本次 setup 不重命名或复制现有术语表。
- 如已有 `GLOSSARY.md`，以其作为术语表读取；如未来出现 `GLOSSARY-MAP.md`，按其中的上下文指针读取相关术语表。
- 读取 `docs/adr/` 中与当前工作相关的决策。现有决议还记录在 Wayfinding 工单及规格文档引用的工单中；触及对应领域时沿相关引用读取正文和决议评论。

## 使用与维护

工单标题、设计、测试和报告沿用现有领域词汇；术语表只记录领域含义，不放实现步骤。存在与既有决议的冲突时，明确说明冲突及建议重审的理由。

`GLOSSARY.md` 和 ADR 按需创建：有真实术语迁移或已形成的架构决策时再写，不为满足目录结构生成占位内容。引用的可选领域文档尚不存在时继续任务。
