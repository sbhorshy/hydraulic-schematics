> 日期：2026-08-31。**原型票：不定案，待人工反应后定路线。**

## 实验设置

- **冻结沙箱** `proto/frozen/`：自 git HEAD（e9619cb，基线 #11 度量时的状态）整体抽出，intent/catalog/渲染器/符号与基线严格同源，且与并发进行中的工作目录改动零冲突。
- **路线 A**（`proto_a_kiwi.py`，224 行）：kiwisolver（Cassowary/Kiwi，pip 现成）声明式约束——REQUIRED（画布/图例回避、B5 盒距、母线次序与挂接净距、行列对齐）+ 强/弱偏好锚点，坐标全部为求解器输出。
- **路线 B**（`proto_b_rules.py`，366 行）：母线驱动规则式分层——从 intent 链路与 catalog 端口 role 推导链表/母线类别，按规则参数表（P）解算全部坐标；不读 v2.3 任何坐标数字。
- 两路线共用同一张约定参数表与符号足迹表（符号 w/h/rot 是库事实，非布局决策），共用 render.py 的 route() 走线，**对比隔离的正是"坐标怎么来"这一层**。
- 校核：validate_sheet.py B1–B7 面板 + 全项几何校核；每个变体用它自己的 SVG 重生成回读 PNG（V16 像素判据的证据必须与被检图同源——本轮踩坑后固化的协议）。

## 关键发现

1. **两条路线都能在 1# intent 上一次生成基线等级的图**：零手工坐标、fail 0，B1–B7 与基线持平或略优（A 的 B4=12 反而消掉了基线的压线）。基线里 2 小时/4 轮的人工布局迭代，被两条路线各自压缩到一次生成+微调。
2. **失败模式不同，这是选型的真正分野**：
   - A 的失败全是**约束缺口**现形：元件骑母线（±80 带无下限 → 37× 绕行）、净距没留引出桩+桥半径（→ 3px 短段）、abs() 非线性（→ 改线性对）、REQUIRED 与 REQUIRED 冲突（→ 强度分级）。每一条修法都是"补一条声明"，且求解器保证补完后不再退化。
   - B 的失败全是**规则程序 bug**（漏分支、字段遗漏、族误判），修法是改代码，正确性靠测试与校核兜底，没有"声明即正确"的结构性保证。
3. **每条隐式人类惯例都必须显式化**——两条路线共同的代价：母线净距 = 18px 引出桩 + 8px 预算最短段 + 5px 桥半径 + 裕量 ≈ 40px，这类数字原来是人工四轮返工的"肌肉记忆"，现在是参数表/约束里的一条声明。
4. **改参传播两者都通过**：行距 320→420 双双零改动吸收。差异在保证方式（A 求解器结构性保证、B 靠规则代码正确性），不在本轮实测结果。
5. **工程衔接零障碍**：两者输出物与 v2.3 layout.json 同构，render.py/validate_sheet.py 一行未改。

## 建议（供定案参考，未定案）

调研票的推荐排序成立：**路线 B（母线驱动规则式分层）为正式实现的首选**——零依赖、warn 与基线持平、B3 略优、修正轮数少一轮；**路线 A 的价值在补强而非替代**：把 B 的规则输出作为初解、用 A 的约束层做一致性守门与微调（"规则定拓扑行位、约束微调坐标"的混搭形态），可作为正式实现票的备选形态一并定案。

也可以按 B 走，把 A 的教训（净距=桩+最短段+桥半径、元件禁骑母线）沉淀进 B 的规则注释与校核处方表。
