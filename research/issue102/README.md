# 回读分诊决策原型（[回读反馈：怎样排序问题并给出可执行的修图建议？](https://github.com/sbhorshy/hydraulic-schematics/issues/102)）

一次性原型，**不合并到 main**。回答的问题：回读页怎样帮助审阅者更快找到问题并开始下一轮修图，具体定四件事——优先顺序、每个问题保留什么、哪些给结构化建议、建议怎么接局部自动修正和图像差分。决议在票的决议评论里；这份 README 只记原型怎么跑、用了什么样本和哪些事实是查过的。

## 文件

- `../../.agents/skills/hydraulic-schematic/scripts/proto_issue102_readback_triage.py`：一次性分诊核心，纯函数：把官方 validation report 的条目按同处 / 同一连线并成问题，判类别、严重度、相对冻结上一版的「新增 / 仍在 / 已消除」，给原因、嫌疑对象、三段描述、修正动作、fix path、`sheet_diff` 口径的 scope，以及四种排序。没有 IO、没有 DOM，尚未接进 `readback_review`。
- `make_cases.py`：从 1# 输入派生工作目录，注入一处或几处显式改动，逐张走官方链 `render → rasterize → validate → readback generate`；产物写到被忽略的 `.artifacts/issue102/cases/<名字>/`。
- `build_prototype.py` + `prototype.js` + `prototype.css` → `readback-triage-prototype.html`：把 21 张图的报告、官方回读页原样、PNG 和分诊结果打进一个 14 MB 的单文件决策页；双击即可打开，不需要服务端，状态只在内存里。
- 页面四个版本：`A 现状`（官方 `readback.html` 原样，只注入计时埋点）、`B 按严重度平铺`（只排序，不合并）、`C 按类别分诊`（并成问题 + 原因 / 嫌疑 / 建议 + 三级局部图）、`D 按位置的修图路线`（全图编号 + 路线 + 修图单）。底部开关或 ← → 切换。
- 页面「四个决定」四个 tab：排序规则与客观核对、三级局部图与范围、缺陷种类 → 建议去向（可点着改）、修图单与差分范围（含两轮模拟）。「对照试验」是盲投用的：4/8/16 张、随机配版本，记找到第一个主要问题的用时、打开 / 看到的局部图数、点击位置、把握和「建议够不够」；结果可导出 JSON / TSV。

## 复现

在仓库根目录：

```bash
python3 research/issue102/make_cases.py
python3 research/issue102/build_prototype.py
```

第一次约几分钟（21 次官方出图链），第二次打包约 10 秒。重建后直接双击 `research/issue102/readback-triage-prototype.html`；`?variant=A|B|C|D` 可以直接进某个版本。运行产物只在被忽略的 `.artifacts/issue102/`，不随分支走。

## 样本与客观核对

样本来自对基线布局逐个元件做单点扰动（旋转 ±90/180、平移 ±60/±120、母线 ±30/±60）共 231 次的扫描：106 次被硬性走线门槛挡住，125 次出图，3 次零失败。这里按「主要失败类别」分层取图，每层 4 张（标签重叠 / 连接语义 / 版式与预算），另有基线、遮挡、单母线、两张多因混合图，共 21 张；每张图只有一处或几处显式改动，所以「排在第一位的问题有没有点名被改动的对象」可以机器判。

21 张图（除基线外 20 张改过）里，四种排序规则下第一位问题都点名了改动对象，`B` 平铺的第一条也都对；页面「客观核对」表逐张列出。分诊做了两条与排序无关的校正：

- 一处改动会散成多条报告条目：`mix-3` 的 45 条新增候选条目并成 4 个问题，`multi-bus` 的 28 条并成 1 个，`label` 的 15 条并成 2 个，`topology` 的 10 条并成 1 个。
- 问题不一定落在被改的对象旁边：`crossing-prv` / `overlap-prv` 里 PRV-002 被挪走后，路由器把 `paths[4][0->1]` 改了走向，新交叉出现在 PF-001 附近。嫌疑对象因此也认「自己端点没动、但和上一版画得不一样」的走线。

修图单的 `diff_scope` 用 `sheet_diff._scope` 实际校验过，21 张、每种规则都通过；母线锚点并进 `edges`。`sheet_diff` 要求拓扑覆盖 pass 且几何无问题，所以连接语义的失败没修完时图像差分不可用——页面把这一点直接写在「衔接」里，而不是假设差分总能用。修正最多两轮，每轮只修上一轮列出的缺陷，第二轮之后停手出未收敛项清单。

## 页面里查到的事实（不是提议）

- 官方回读页的对象清单没有失败 / 提示标记；失败与提示条目从第 101–116 行开始（各图不同），混在 106–164 行、约 59–64 张局部图里。
- V13 / B2 / B3 三类条目只链到「全图」，没有局部图；`multi-bus` 有 32 条、`mix-3` 有 33 条只链全图。
- 「共线重叠但汇于同一端口」是提示，按连通处理，不必修；图面可读性评分那一票定的四项指标（单条主线折点 > 6、三通旁线段 < 30 px、标签离主人 > 40 px 或离别的元件更近、异网并行中心距 ≤ 16 px 且并行 ≥ 24 px）还没进官方报告。主线折返、三通互距、跨线桥到最近节点只是低信号回读提示。

## 口径与 caveat

- 图只覆盖 1# 一份输入；样本是为找极值做的定向改动，不是常见程度。试验设计是一人做、每版本 2 张，只能看方向，有学习效应；记录只在内存里，刷新即清空。
- 页面里的「新增 / 仍在 / 已消除」是拿冻结的基线图作上一版算的；选「不比对」后所有条目都退回「未比对」，没有假装知道历史。
- 「建议够不够」在 A 里换成自由文本，因为现状页没有建议可评分；点击位置的命中范围是「新增问题框 ∪ 改动对象足迹」外扩 40 px。
- 分诊逻辑是一次性原型，不在 skill 的调用链上；页面上的临时改动（去向、修因开关）只影响本页显示，JSON 面板给的是模块原样。
