# #23 当前 1# 输入的固定端口环序阻断：独立 Spec 核对

**结论：阻断成立。** 对当前项目的真实 intent、端口资产及现行连续管线/禁镜像/不换端口/B1=0 规则，单靠重新布局、增大画幅、绕行或四向旋转，无法得到全链 fail 0。本结论不是说抽象 K₂,₃ 非平面，而是该子图的**固定旋转系统**不允许平面嵌入。

## 从实际输入独立核实

- `1#系统原理图/1#系统.intent.yaml` 的 paths[0]/[1] 分别把 EMP.suction、经 FSOV 的 EDP.suction 接到同一 TANK.suction_out；paths[2]/[3] 接同一 @PRESS；paths[29]/[30] 接同一 @CASE。三条液压网络身份不同，不能靠误接、并网或跳接消除交叉。
- 项目 layout 和 catalog 同时选择实际 `symbols/edp-provisional-stroke.svg`、`symbols/emp-provisional-stroke.svg`。两资产 viewBox 都是 0 0 80 80；S=(0,40,left)、P=(80,40,right)、C=(40,80,down)。以 SVG 坐标同一方向绕行，环序均为 P→C→S（循环起点无关）。两个 catalog 条目允许 0/90/180/270 且 `allow_mirror=false`。
- FSOV 的 catalog 主路为 main_upper→main_lower。在所选子图中它是度 2 串联构件，收缩不改变任一泵的三口环序。其余图元和支路可删去：若全图存在合法无交叉图，删去它们后这个子图也必须可平面绘制。

## 独立计算与证明

我从上述实际 SVG 提取三口坐标，独立构造两泵—S/P/C 的 K₂,₃ 固定环序；用 NetworkX 3.3 的 `PlanarEmbedding.traverse_face` 枚举面并以 `check_structure` 检查，不复用根探针的面遍历实现。

- 同环序：V=5、E=6、F=1，Euler 数 5−6+1=0；平面连通嵌入要求 2，检查拒绝。抽象图 planarity 检查同时返回 true。
- **仅作反事实对照**，把一泵环序反转：F=3、Euler 数=2，固定嵌入检查通过。
- 任何允许的旋转都保持平面朝向，只循环移动环序起点，不会把 P→C→S 改为 P→S→C。因此两个泵的 16 个旋转组合都属于同一个被拒绝的旋转系统，无须靠有限布局搜索猜测结论。

独立证据（含资产 SHA-256、实际路径索引、面边界及正反对照）：[independent-fixed-rotation.json](independent-fixed-rotation.json)。另已阅读 baseline 的 [check_rotation_obstruction.py](check_rotation_obstruction.py)，其自动提取和 16 组合证书与上述独立结果相符。

这里把泵看作不可穿越的端口圆盘，是对现行 V2/端口外向引出和 B5 分离约束的拓扑抽象，不是把三液口改成同一液压节点。沿每个互不误接的 S/P/C 网络各取一条两泵间路径即可；额外绕行、分叉或母线长度不会改变端口环序。跨线桥仍违反 B1；故在保持合法连续连接、不穿体、不误接的前提下，至少一个非连接交叉不可避免。

## 验收与裁决边界

#23 原文仍要求“到站链全量回归：fail 0、B 面板不劣于到站水平（B3 ≤1.447、B4/B5 不压线）”。本结论不删除或放宽该要求：#23 保持开放，坐标迁移实现及旧 seed 等价证据可独立成立，完整到站验收受现有约束组合阻断。

之前“可用当前已更新 1# 输入的新验收布局补齐证明”的解释，说明的是输入版本不必锁死旧 22 件；**不保证这样的布局在现行约束下存在**。现在独立证据证实其不存在，应停止盲搜。

解除阻断需有权限的工程/规范裁决改变至少一项实质约束，例如：在 #63 类镜像裁决中明确是否及如何覆盖这些泵；依据真实标准/工程资产重新定档一泵的端口环序；或正式重审 B1 对有定义的非连接跨越/表达机制的限制。真实拓扑修订也须工程依据，不能为了出图擅自改网。反转一泵仅证明这处局部拓扑阻断消失，不承诺全图所有预算随即满足。现有 #63 围绕 RF 的讨论不自动授权镜像 EDP/EMP。

本次没有改变源码、输入、资产、预算或签认状态，未运行全量测试，也不扩入 #45 缺事实类型或重写冻结历史。
